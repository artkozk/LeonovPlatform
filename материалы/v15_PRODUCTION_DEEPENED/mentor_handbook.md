# Handbook для наставника v15

## Принцип ответа
Сначала выясни наблюдаемый результат: условие, код, команда запуска, вход, stdout, stderr, статус HTTP, SQL result set или состояние git. Не выдавай готовое решение, если можно довести студента вопросами до локализации ошибки.

## Когда давать подсказку
1. После первой неудачной попытки укажи область: ввод, преобразование, формат вывода, SQL-порядок, status code, git-state.
2. После второй попытки дай короткий фрагмент правила, но не полный код.
3. После третьей попытки можно показать минимальный пример на другой задаче.
4. Полное решение показывай только после pass/fail политики платформы или при разборе после дедлайна.

## Типовые ошибки по модулю 1
- stdout содержит лишнее слово или пробел;
- `input()` не преобразован через `int`/`float`;
- переменная используется до создания;
- Git-лаба сдаётся с грязным рабочим деревом.

## Типовые ошибки по модулю 2
- функция печатает результат вместо return;
- pytest-тест зависит от порядка запуска;
- mock скрывает настоящую ошибку контракта;
- async-код создаёт coroutine, но не await.

## Типовые ошибки по модулю 3
- LEFT JOIN превращён в INNER JOIN из-за фильтра в WHERE;
- SQL без ORDER BY даёт нестабильный результат;
- транзакция не делает rollback при ошибке;
- sqlite3-код забывает commit или использует строковую склейку вместо параметров.

## Типовые ошибки по модулю 4
- FastAPI возвращает 200 вместо 201/204/404/422;
- healthcheck возвращает массив вместо объекта;
- Dockerfile копирует лишние файлы или CMD не стартует приложение;
- CI объединяет lint/test/build/deploy в один непрозрачный job.

## Типовые ошибки по модулю 5
- AI provider вызывается напрямую без timeout/retry/mock;
- RAG отвечает без ссылок на найденные chunks;
- deploy script не имеет dry-run и rollback;
- финальный проект не содержит acceptance criteria и negative tests.

## Как проверять финальный проект
Проверь gates отдельно: ТЗ, user stories, ERD, миграции, API contract, auth, CRUD, tests, Docker, CI/CD, AI integration, logging, README, deploy, defense. Для каждого gate должен быть артефакт, команда проверки, pass/fail критерий и понятный риск.

## Жалобы на hidden tests
Не отвечай фразой «у тебя ошибка». Попроси публичный пример, локальный запуск, версию файла, команду и минимальный reproduction. Эскалируй, если публичный тест противоречит hidden-проверке или hidden требует того, чего нет в условии.

## Маршруты восстановления
- Отстаёт Python Core: верни на последние 5 stdout/pytest-задач и проверь базовый ввод/return.
- Отстаёт SQL: дай 10 запросов на SELECT/WHERE/JOIN/GROUP BY с обязательным объяснением каждой строки.
- Отстаёт Git: запрети force-команды, создай recovery branch, повтори restore/reset/revert/reflog на песочнице.
- Отстаёт FastAPI: начать с `/health`, затем один POST, затем один negative 422.
- Отстаёт DevOps: сначала локальный запуск без Docker, потом Dockerfile, потом compose, потом CI.

## Эскалация
Эскалируй методисту или инженеру платформы, если корректное решение падает на инфраструктуре, IDE-плагин не видит существующий файл, hidden tests проверяют неописанное поведение или массово повторяется одна и та же ошибка формулировки.
