# Release Checklist

## Перед импортом
- `python validate_course.py` завершился успешно.
- `validation_report.md` показывает `Final status: PASS`.
- Первый урок: Модуль 1 → Урок 1 → `Первый код`.
- `manifest.csv` совпадает с JSON по количеству уроков и шагов.
- `coverage_matrix.csv` не содержит статусов `missing`, `thin`, `placeholder`.
- Все practice имеют checker.
- Все project имеют IDE-plugin проверку или AI-review.
- Все test имеют structured `questions[]`.

## После импорта
- Количество модулей, уроков и шагов на платформе совпадает с manifest.
- Первый видимый шаг открывается студенту.
- Практика Python запускает checker.
- SQL-задача видит schema SQL и seed SQL.
- FastAPI-задача запускает HTTP checks.
- Проектный шаг получает IDE-plugin report.
- AI-подсказка не раскрывает solution_code и hidden cases.

## Почему чеклист отдельный
Он нужен операционной команде перед запуском потока. Валидатор проверяет структуру файлов, а чеклист закрывает ручную часть импорта и smoke-проверку платформы.

## Поправки качества от 2026-05-01
Историческая проблема: первая версия проходила структурную проверку, но проваливала содержательный quality gate из-за повторяемых теорий, однотипных `solve(a, b)`, одинаковых SQL-условий и общих проектных требований.

Как работает сейчас: генератор создаёт доменно-специфичные объяснения, отдельные pytest-функции по урокам, согласованные SQL-условия с решениями, более предметные проектные требования и отдельный quality gate в валидаторе. Это сделано, чтобы ревьюер видел не только импортируемую структуру, но и защиту от возврата к однотипным заготовкам.

Ограничение: это всё ещё текстовый курс, а не видеопрограмма. Для запуска большого потока нужны пилот, редакторская вычитка, проверка первых сдач, настройка наставнических сценариев и регулярное улучшение hidden cases.
