# Mentor Handbook

## Роль наставника
Наставник помогает студенту найти ошибку, но не заменяет его работу готовым решением. В этом курсе большинство шагов уже имеют автоматическую проверку, поэтому ручная помощь нужна для диагностики, архитектурных решений и восстановления после тупика.

## Частые ошибки
- Лишний вывод в stdout-задачах.
- Подмена `return` на `print` в функциях.
- SQL без условия соединения.
- `LEFT JOIN`, который стал обычным соединением из-за фильтра в WHERE.
- SQLite без `commit()` или без закрытия соединения.
- FastAPI endpoint без `response_model` и явного status code.
- Dockerfile без `.dockerignore`.
- Git-история с незакоммиченными файлами перед сдачей.
- Секреты в коде вместо `.env.example`.

## Как отвечать студенту
Сначала попроси показать вход, фактический результат и ожидаемый результат. Затем дай направление: файл, функция, условие, команда. Если студент просит готовый код, покажи минимальный фрагмент на другом примере и попроси применить принцип к своей задаче.

## Где не давать готовое решение
Не отправляй полный код для практики, проектного gate, SQL-запроса или финального проекта. Исключение: техническая проблема платформы, где код студента уже корректен, а проверка сломана.

## Как проверять проекты
Смотри на IDE-plugin report, затем README, затем структуру файлов, затем тесты, затем Git. Если базовая механика не проходит, AI-review по архитектуре не имеет смысла.

## Эскалация
Эскалируй в методическую команду, если условие противоречит checker, hidden case требует неописанное поведение, фикстура повреждена или платформа показывает другой порядок шагов, чем `manifest.csv`.

## Маршруты восстановления
- Python Core: вернуться к минимальному примеру и точному выводу.
- SQL: нарисовать таблицы, связи и ожидаемые строки.
- FastAPI: проверить путь, метод, статус и JSON.
- Docker: запустить `docker compose config`, потом логи сервиса.
- Git: сохранить патч, восстановить чистое дерево, повторить команды осознанно.
