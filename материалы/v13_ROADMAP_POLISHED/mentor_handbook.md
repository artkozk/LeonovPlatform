# Handbook для наставника

## Как отвечать
Отвечай вопросом к наблюдаемому результату: что студент запустил, какой ввод дал, какой вывод получил. Не выдавай полное решение, если ошибка находится через один локальный запуск.

## Частые ошибки
- лишний вывод в stdout-задачах;
- SQL без стабильной сортировки;
- забытый `commit()` в sqlite3;
- FastAPI endpoint возвращает неверный статус;
- Dockerfile копирует лишние файлы;
- Git-задача с грязным рабочим деревом.

## Где не давать готовое решение
Не пиши полный код для практики, если можно указать место проверки: вход, преобразование, формат вывода, статус ответа, SQL-сортировка.

## Эскалация
Эскалируй платформенную ошибку, если локально правильное решение не проходит проверку, публичный пример противоречит условию или IDE-плагин не видит существующий файл.

## Маршруты восстановления
Для Python вернись к первому падающему примеру. Для SQL проверь схему и seed. Для Git создай резервную ветку перед исправлением истории. Для Docker сначала запусти приложение без контейнера.
