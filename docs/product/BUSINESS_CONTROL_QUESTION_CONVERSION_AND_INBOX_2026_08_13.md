# Преобразование задачи и персональная очередь вопросов

Дата: 13 августа 2026 года.

Документ фиксирует текущее поведение после добавления безопасного преобразования задачи в карточку вопросов и персональной очереди ожидающих ответов. Он дополняет описание основного процесса вопросов и не удаляет прежние решения.

## Практическая причина релиза

Первая production-запись `Список вопросов до начала работы` была создана как обычная задача до появления специализированной карточки вопросов. Создание новой карточки и ручное копирование нарушило бы главный инвариант продукта: один объект должен существовать в единственном экземпляре, постепенно заполняться, менять состояние и сохранять всю историю.

Поэтому система теперь умеет менять назначение существующей задачи без создания второго объекта. Дополнительно главный экран показывает не абстрактное число обсуждений, а вопросы, на которые текущий пользователь ещё не ответил. Это превращает процесс вопросов в ежедневный рабочий сценарий.

## Как преобразовать задачу

1. Открыть задачу.
2. На вкладке `Обзор` нажать `Сделать карточкой вопросов`.
3. Проверить и при необходимости изменить причину преобразования.
4. Подтвердить действие.
5. После преобразования открывается вкладка `Вопросы и ответы` той же карточки.
6. В поле `Один вопрос на строку` вставить подготовленный список и нажать `Добавить в карточку`.

Каждая непустая строка становится отдельным вопросом внутри одной групповой карточки. Нумерация вида `1.`, `1)` и маркеры списка убираются автоматически.

## Что сохраняется

При преобразовании не меняются:

- идентификатор карточки;
- название и описание;
- автор и ответственный;
- срок;
- плановая оценка времени;
- связи с другими карточками;
- дата создания;
- вся предыдущая лента событий.

Тип хранения меняется с `task` на внутреннюю пару `document + question_set`. API и интерфейс показывают её как `question_set`. Статус становится `planned`, а после добавления первого вопроса автоматически переходит в `in_progress`. Прогресс далее рассчитывается по количеству вопросов с совместным итогом.

## Защита от потери данных

Преобразование разрешено только для задачи. Сервер отклоняет действие, если:

- карточка уже является карточкой вопросов;
- карточка находится в архиве;
- в ней есть заполненный результат;
- приложено хотя бы одно доказательство выполнения;
- существует сохранённый раскрываемый раздел с непустым содержанием;
- переданный `expectedUpdatedAt` не совпадает с текущей версией карточки;
- причина не указана.

Ограничения сделаны намеренно. Доказательство, результат или заполненный раздел имеют другой смысл в процессе вопросов и не должны становиться невидимыми после смены интерфейса. В такой ситуации пользователь сначала переносит важный текст в описание либо оставляет исходную задачу и создаёт связанную карточку вопросов.

## История преобразования

Успешное действие создаёт событие `converted_to_questions`. В событии сохраняются:

- автор действия;
- дата и время;
- тип до и после;
- статус до и после, только если статус действительно изменился;
- прогресс до и после, только если значение действительно изменилось;
- обязательная причина.

Неизменившиеся поля не добавляются в сравнение, поэтому история не показывает бессмысленные строки вроде `0% → 0%`.

## Персональная очередь ответов

Новый endpoint `GET /api/questions/pending` возвращает открытые вопросы, для которых у текущего пользователя нет ответа. Запрос учитывает только активные карточки вопросов и не включает:

- решённые вопросы;
- архивированные вопросы;
- отменённые карточки;
- архивированные карточки;
- вопросы, на которые текущий пользователь уже ответил.

Результат персонален. После ответа `artkozk` вопрос исчезает только из его очереди, но остаётся в очереди `sweetybboy`, пока тот не сохранит собственную позицию.

На обзоре очередь используется в двух местах:

1. Метрика `Ждут ответа` показывает количество личных ожидающих вопросов.
2. Блок `Фокус на сегодня` показывает текст конкретного вопроса, исходную карточку и срок обсуждения. Клик открывает карточку сразу на вкладке вопросов.

Срочные и просроченные задачи остаются выше вопросов. Ожидающие ответы располагаются перед обычными задачами без срочного срока. Так сохраняется приоритет сроков и одновременно не теряется совместная работа.

## Работа до регистрации партнёра

Платформа рассчитана на двух основателей. Раньше при единственном зарегистрированном аккаунте один пользователь считался полным составом и мог зафиксировать «совместное» решение самостоятельно.

Теперь минимальное ожидаемое число ответов равно двум:

- карточка показывает панель текущего пользователя;
- вместо отсутствующего аккаунта показывается панель `Второй основатель`;
- в ней объясняется, что после регистрации партнёр увидит вопрос в личном фокусе;
- сервер не принимает совместный итог, пока зарегистрировано меньше двух участников;
- после регистрации нужны ответы всех зарегистрированных участников.

Это ограничение относится только к совместному итогу. Первый основатель может заранее создать карточку, внести список и подготовить собственные ответы.

## API

### Преобразование

```http
POST /api/records/{recordId}/convert-to-questions
Content-Type: application/json

{
  "reason": "Задача изначально создана для совместной проработки списка вопросов",
  "expectedUpdatedAt": "2026-08-13T00:58:05.812243Z"
}
```

Успешный ответ содержит ту же запись с `type: question_set`. Конфликт содержимого или версии возвращает HTTP `409`, отсутствие причины возвращает HTTP `400`.

### Ожидающие ответы

```http
GET /api/questions/pending
```

Элемент ответа содержит `questionId`, `body`, `recordId`, `recordTitle`, `dueAt` и `createdAt`. Полного содержимого карточки в этом списке нет; оно загружается существующим быстрым endpoint карточки после клика.

## Проверки

Интеграционные тесты подтверждают:

1. преобразование сохраняет ID, срок и оценку времени;
2. задача становится карточкой вопросов со статусом `planned`;
3. задача с доказательством не преобразуется;
4. до ответов один и тот же вопрос присутствует в очередях обоих пользователей;
5. после ответа первого пользователя вопрос исчезает только из его очереди;
6. при одном зарегистрированном пользователе workflow всё равно ожидает два ответа;
7. сервер отклоняет совместный итог с одним ответом.

В браузере проверен полный сценарий: создание задачи со сроком и оценкой, открытие карточки, подтверждение преобразования, сохранение срока и описания, добавление вопроса, появление вопроса в личном фокусе и отображение отсутствующего второго основателя.

## Следующие улучшения

После этого релиза приоритет ежедневной работы остаётся у следующих функций:

- приоритет и чек-лист задачи;
- уведомление о назначении и приближении срока;
- этап отправки результата на проверку;
- несколько участников общей задачи с отдельной оценкой времени;
- комментарии и упоминания внутри карточки;
- серверная пагинация истории и списков.
