# BizFlow: режим чтения и визуальный редактор

Дата: 14 августа 2026 года.

## Почему потребовалась корректировка

Предыдущий релиз добавил Markdown и полноэкранный блокнот, но смешал две разные задачи. Пользователь, который открывал готовый ответ, видел действие для запуска отдельного окна чтения. Пользователь, который редактировал ответ, видел исходные символы Markdown. Длинный ответ мог обрезаться градиентом, а соседняя колонка растягивалась по высоте. Форматирование через браузер иногда не попадало в историю `Ctrl+Z`.

Это противоречило основной модели продукта: повторное открытие карточки предназначено для чтения и оценки результата, а изменение должно быть отдельным осознанным действием.

## Актуальная модель

### Чтение

Сохранённое описание, ответ, вывод или другой длинный текст отображается как готовый документ. Markdown преобразуется в безопасный HTML через локальные Marked и DOMPurify, поэтому пользователь видит заголовки, списки, акценты, цитаты и ссылки, но не служебные символы разметки.

Если высота документа превышает 440 px, под ним появляется действие `Показать полностью`. Оно расширяет содержимое внутри той же карточки. Повторное нажатие `Свернуть` возвращает компактное представление. Отдельный диалог и размытие экрана для чтения не используются: вопрос, автор, статус и ответ партнёра остаются в поле зрения.

Короткий текст не получает лишнюю кнопку. Решение принимается после фактического измерения высоты отрисованного документа, а не по приблизительному числу символов.

### Редактирование

Собственный сохранённый ответ сначала открывается для чтения. Кнопка изменения доступна только пользователю с правом редактирования. После её нажатия появляется визуальный редактор и действия `Сохранить ответ` и `Отмена`. Для ещё не заполненного собственного ответа редактор показывается сразу, потому что читать пока нечего.

Визуальный редактор использует `contenteditable`: форматирование применяется непосредственно к тексту. Скрытое исходное поле синхронизируется после каждого изменения и передаёт серверу Markdown. Серверный контракт и существующие данные не меняются, а пользователь не работает с `**`, `#` и другими служебными маркерами.

Полноэкранный блокнот открывается только из панели активного редактора. В нём нет второй колонки предпросмотра: документ уже редактируется визуально. `Ctrl/Cmd+Enter` применяет текст обратно в исходную форму, после чего обычная кнопка карточки сохраняет изменение на сервере.

## Форматирование и история

Поддерживаются:

- `Ctrl/Cmd+B` — полужирный текст;
- `Ctrl/Cmd+I` — курсив;
- `Ctrl/Cmd+K` — ссылка;
- `Ctrl/Cmd+Alt+2` — заголовок второго уровня;
- `Ctrl/Cmd+Shift+7` и `Ctrl/Cmd+Shift+8` — нумерованный и маркированный списки;
- `Ctrl/Cmd+Shift+.` — цитата;
- `Ctrl/Cmd+Backtick` — блок кода;
- `Ctrl/Cmd+Z` — отмена;
- `Ctrl/Cmd+Y` или `Ctrl/Cmd+Shift+Z` — повтор отменённого изменения.

Для отмены редактор хранит до 120 собственных снимков HTML и синхронизированного Markdown. Это необходимо, потому что встроенная история `contenteditable` по-разному учитывает команды форматирования в разных браузерах. Восстановление снимка одновременно обновляет визуальный документ и отправляемое поле, поэтому после `Ctrl+Z` сервер не получает уже отменённое форматирование.

Вставка из буфера выполняется как обычный текст. Это не позволяет принести в карточку стили, скрытые элементы и небезопасный HTML из внешнего сайта. Требуемое форматирование добавляется средствами BizFlow.

## Сравнение вариантов

Значения общих полей варианта больше не обрезаются однострочным многоточием. Длинная конфигурация переносится по словам и при необходимости внутри непрерывного значения. Карточка может стать выше, но пользователь видит данные полностью и сравнивает варианты без переключения в форму.

Горизонтальная лента вариантов сохраняет drag-scroll мышью. Начало перетаскивания временно отключает выделение текста; обычный клик и выделение внутри неподвижной карточки остаются доступны.

## Инварианты

- Режим чтения не содержит редактируемых полей.
- Разворачивание чтения не создаёт новый modal или browser history entry.
- Блокнот не открывается из готового документа.
- Отмена редактирования не отправляет запрос и возвращает сохранённое состояние.
- Markdown остаётся единственным хранимым текстовым форматом; визуальный HTML не записывается в БД.
- DOMPurify очищает существующий Markdown до помещения в `contenteditable` и в режим чтения.
- Права изменения ответа не расширяются новым редактором.

## Проверка

Browser QA проходит следующие сценарии:

1. Ввести текст, применить `Ctrl+B`, отменить `Ctrl+Z`, сохранить и убедиться через API, что маркеры полужирного отсутствуют.
2. После отмены выполнить `Ctrl+Y`, сохранить и убедиться, что Markdown содержит полужирное выделение.
3. Открыть сохранённый длинный ответ и убедиться, что панель редактора скрыта.
4. Развернуть и свернуть ответ внутри карточки, не открывая диалог.
5. Явно включить редактирование, открыть блокнот, отменить изменение и вернуться к чтению.
6. Повторить чтение на ширине 390 px без горизонтального выхода и размытого слоя.
7. Проверить длинное значение параметра сравнения: текст переносится и не получает `...`.

Технические проверки релиза: `go test ./...`, `go vet ./...`, `node --check web/app.js` и `git diff --check`.

## Уточнение статуса AI

В профиле источник рекомендации теперь называется по фактически активному механизму. Если официальный внешний endpoint прошёл health-check, показываются провайдер и модель. Если настроенный Gemini или Groq не отвечает, заголовок сообщает `Локальный анализ активен`, а имя недоступного провайдера, модель и серверное диагностическое сообщение остаются во второй строке. Так локальная эвристика не выглядит ответом внешней нейросети, но причина деградации остаётся доступной без просмотра журнала сервера.
