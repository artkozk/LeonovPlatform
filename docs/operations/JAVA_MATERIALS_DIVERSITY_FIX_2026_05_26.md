# Java Materials Diversity Fix — 2026-05-26

## Контекст

В `java-zero-core` студенты начали получать повторяющиеся практические задания от урока к уроку.  
Сигнал пришел как production-инцидент: «материалы повторяются из задания к заданию».

## Что было сломано

1. Генератор практик в `материалы/java_metanit_v1/build_course.py` использовал ограниченный пул шаблонов.
2. На длинной последовательности уроков это приводило к видимым повторениям задач.
3. Валидация не блокировала низкое разнообразие, поэтому регресс проходил в импорт и миграцию.

## Что исправлено

### 1) Расширен каталог практик

В `материалы/java_metanit_v1/build_course.py` добавлены новые типы задач и вычислители ожидаемых ответов:

- `abs_sum_two`, `product_two`
- `min_three`, `middle_three`
- `odd_count`, `positive_count`
- `uppercase_line`, `word_count`
- `sum_to_n`, `fibonacci_n`
- `char_count`, `substring_overlap`
- `digit_sum`, `gcd_two`, `lcm_two`
- `unique_once_count`

Это увеличило реальное разнообразие практик до 24 шаблонов.

### 2) Изменен выбор шаблона

Выбор шаблона теперь:

1. Делается через стабильный hash от `chapter:page:title`.
2. Имеет анти-повтор: если следующий шаблон совпадает с предыдущим в рамках модуля, берется другой.

Результат: нет повторов шаблона «подряд» в модуле.

### 3) Усилена валидация

Валидации обновлены:

- `материалы/java_metanit_v1/build_course.py` (`validate_course`)
- `backend/tools/validate_java_metanit_v1_import.js`

Новые предохранители:

1. Минимальная диверсификация шаблонов практики.
2. Запрет соседних повторов шаблонов внутри модуля.
3. Ограничение максимальной частоты использования одного шаблона.

## Как применено к данным

1. Пересобраны `practice`-шаги в `материалы/java_metanit_v1/course_import.json` для всех 154 уроков.
2. Сгенерирована новая миграция:
   - `backend/migrations/041_reseed_java_zero_core_metanit_v1_practice_refresh.sql`

Миграция создана отдельным номером, чтобы не переписывать уже примененные миграции в истории.

2. `node backend/tools/validate_java_metanit_v1_import.js` → PASS

## Почему сделано именно так

1. Исправлена первопричина в генераторе, а не только следствие в UI.
2. Добавлены guardrails в обе валидации, чтобы регресс не вернулся при следующей пересборке.
3. Миграция вынесена в новый файл (`041`), чтобы процесс деплоя оставался детерминированным и обратимо-аудируемым.
