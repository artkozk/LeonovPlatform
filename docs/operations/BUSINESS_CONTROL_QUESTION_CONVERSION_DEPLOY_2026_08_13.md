# Production-развёртывание преобразования задачи в карточку вопросов

Дата: 13 августа 2026 года.

Документ фиксирует фактическое развёртывание релиза персональной очереди вопросов и безопасное преобразование первой рабочей карточки. Он дополняет прежние отчёты, не заменяет и не удаляет их: предыдущие точки восстановления остаются частью истории проекта.

## Цель операции

В production уже существовала задача `Список вопросов до начала работы`. Она была создана до появления специализированного процесса вопросов, но фактически являлась группой будущих вопросов основателей. Создание второй записи и ручное копирование нарушило бы продуктовый принцип `один объект -> одна история`.

Операция должна была одновременно:

- развернуть серверную команду безопасного преобразования;
- добавить персональную очередь вопросов без ответа;
- не позволять одному зарегистрированному основателю принять совместное решение;
- сохранить ID, текст, срок, оценку времени, автора и историю существующей карточки;
- оставить проверенную резервную копию до и после изменения данных.

Перед переключением версии подтверждено:

1. DNS домена указывает на ожидаемый production-сервер.
2. `/opt/business-control/current` указывает на релиз `20260813-focus-ui-96e5d12`.
3. `business-control.service` находится в состоянии `active`.
4. `PRAGMA integrity_check` возвращает `ok`.
5. В БД существует ровно нужная рабочая карточка с ID `ec48bd57e6e0e7997f424529a4f42bc0`.
6. Её исходный тип — `task`, статус — `in_progress`, срок — `2026-08-19T21:00:00Z`, оценка времени — `360` минут.
7. В карточке нет результата, доказательств выполнения, заполненных раскрываемых разделов и ранее созданных вопросов.

Последняя проверка важна: при наличии рабочих данных специализированный endpoint возвращает конфликт, поскольку задача и карточка вопросов показывают разные наборы полей. Автоматически прятать существующий результат или доказательство нельзя.

Ссылка `/opt/business-control/current` переключена атомарно через промежуточную ссылку. Скрипт развёртывания содержал автоматический возврат на предыдущий release при неуспешном перезапуске или health check.

Первый запрос во время старта ожидаемо не смог подключиться, после чего повторный цикл получил успешный ответ. Автоматический rollback не потребовался.

## Преобразование существующей карточки

После запуска новой версии условия безопасности были повторно проверены непосредственно в production-БД. Запись преобразована одной транзакцией с условием по:

- точному ID;
- исходному типу `task`;
- исходной версии `updated_at`;
- отсутствию заполненного результата;
- отсутствию доказательств;
- отсутствию заполненных разделов.

Условное обновление изменило ровно одну строку. Итоговое состояние:

- ID: `ec48bd57e6e0e7997f424529a4f42bc0`;
- публичный тип: `question_set`;
- внутренний тип и подтип: `document + question_set`;
- название: `Список вопросов до начала работы`;
- статус: `planned`;
- прогресс: `0%`;
- срок: `2026-08-19T21:00:00Z`;
- оценка времени: `360` минут;
- количество вопросов: `0`.

Отсутствие вопросов является корректным: описание карточки объясняет назначение работы, но не содержит списка, который можно надёжно разбить автоматически. Пользователь добавит каждый подготовленный вопрос отдельной строкой на вкладке `Вопросы и ответы`.

В историю добавлено событие `converted_to_questions` от пользователя с ID `1` (`artkozk`) с причиной `Задача изначально создана для совместной проработки списка вопросов`. Событие содержит изменения типа и статуса. Во время post-check обнаружено удвоение кавычек в служебном JSON из-за экранирования операционной команды; payload исправлен до валидного JSON в той же audit-записи. Проверка `json_valid(details_json)` после исправления возвращает `1`.

## Как продолжить работу в интерфейсе

1. Открыть карточку `Список вопросов до начала работы` в разделе `Вопросы`.
2. На вкладке `Вопросы и ответы` вставить список по принципу `один вопрос на строку`.
3. Нажать `Добавить в карточку`.
4. Ответить на каждый вопрос в своей панели.
5. После регистрации `sweetybboy` вопросы автоматически появятся в его блоке `Ждут ответа`.
6. После двух ответов выбрать один из них как итог либо написать отдельное совместное решение.
7. При необходимости создать из итога связанную задачу одним действием.

Такой порядок сохраняет одну групповую карточку, отдельные сущности вопросов, независимые позиции основателей и общий итог без ручного копирования.
