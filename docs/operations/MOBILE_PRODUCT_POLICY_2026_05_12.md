# Mobile Product Policy Revision — 2026-05-12

## 1. Причина пересмотра mobile-поведения

1. После предыдущего mobile hotfix выяснилось, что header на телефоне всё ещё воспринимается как слишком высокий и визуально «съедает» значимую часть первого экрана.
2. Дополнительно зафиксировано продуктовое замечание: сценарий написания и отправки кода с маленького экрана ухудшает UX (набор, навигация по редактору, чтение логов, сравнение условия и решения).
3. По результату принято решение разделить роли устройств:
- телефон: навигация, теория, квизы, просмотр задач;
- ПК/ноутбук: полноценный coding-flow (редактор, запуск, отправка, подсказки, логи).

## 2. Что было до изменения

1. Header на mobile показывал полный блок навигации и user controls сразу, без обязательного collapse.
2. На страницах с кодом (`/tasks/:taskId` и практические шаги в `/lessons/:lessonId`) редактор и действия были доступны на всех размерах экрана.
3. Формально сценарий работал, но фактически на узких экранах он давал низкую usability-оценку.

## 3. Что изменено в коде

## Шаг 1. Компактный мобильный header с ручным раскрытием меню

1. Файл: `frontend/src/components/AppLayout.tsx`.
2. Добавлен state `mobileNavOpen`.
3. В header добавлена верхняя строка `app-header-top-row`:
- бренд;
- кнопка `app-mobile-menu-toggle` (`Menu/X`).
4. Навигация и user-zone получают класс `is-open` только когда меню раскрыто.
5. При смене маршрута меню автоматически закрывается, чтобы новый экран открывался в компактном состоянии.

## Шаг 2. Финальные CSS-правила для mobile collapse

1. Файл: `frontend/src/styles/global.css`.
2. Добавлены базовые классы:
- `.app-header-top-row`;
- `.app-mobile-menu-toggle`.
3. В `@media (max-width: 1080px)`:
- `.app-nav` и `.app-user-zone` скрыты по умолчанию;
- отображаются только как `.is-open`;
- профильный dropdown на mobile становится статическим блоком внутри раскрытого меню.
4. Результат: в закрытом состоянии header занимает минимальную высоту, а не половину экрана.

## Шаг 3. Политика desktop-only для code-flow (до 1024px)

1. Добавлен hook `frontend/src/hooks/useIsSmallViewport.ts`.
2. `TaskPage` (`frontend/src/pages/TaskPage.tsx`):
- при `max-width: 1024px` редактор и submit-flow не рендерятся;
- остаётся условие задачи и явное сообщение с переходами к спискам.
3. `LessonPage` (`frontend/src/pages/LessonPage.tsx`):
- для `practice/project` шагов при `max-width: 1024px` скрыт блок редактора и действий;
- показывается сообщение, что кодинг доступен с большого экрана;
- теория и quiz-шаги сохраняются на mobile.

## Шаг 4. UX-оформление блокировки

1. В `frontend/src/styles/global.css` добавлены классы:
- `.coding-desktop-guard`;
- `.coding-desktop-guard-actions`;
- `.coding-desktop-guard-inline`.
2. На узких экранах кнопки в блоке ограничения растягиваются в колонку для удобного тапа.

## 4. Как работает сейчас

1. На телефоне header по умолчанию компактный.
2. Пользователь сам раскрывает навигацию по кнопке меню.
3. Кодовые задачи и практики не дают писать/отправлять код с маленького экрана.
4. Учебный контент, структура курса и quiz-поток доступны на телефоне.

## 5. Почему выбрано именно это решение

1. Это адресный продуктовый компромисс:
- не ломается мобильное обучение как таковое;
- убирается неудобный и шумный mobile coding-flow.
2. Изменение минимально рискованно:
- не меняется backend-контракт;
- изменения локализованы в layout/pages/styles.
3. Для reviewer прозрачна мотивация:
- это не «косметика», а управление UX-границами устройства для основной воронки обучения.

## 6. Валидация после изменения

1. `cd frontend && npm.cmd run build` — PASS.
2. `cd frontend && npm.cmd run lint` — PASS по ошибкам (остаются только исторические warnings, не связанные с текущим изменением).

## 7. Что проверять вручную в QA

1. `/dashboard` на `360px`: header закрыт, меню раскрывается/сворачивается.
2. `/tasks/:taskId` на `360px` и `390px`: виден guard-блок, редактор отсутствует.
3. `/lessons/:lessonId`:
- theory/quiz шаги работают на mobile;
- practice/project шаги показывают guard-блок вместо редактора.
4. На desktop (`>=1280px`) весь code-flow доступен как раньше.
