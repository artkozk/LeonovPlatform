# SUPPORT UI Style Regression Fix — 2026-05-25

## Контекст инцидента

На production в интерфейсе поддержки (`/support`, `/admin/support`) произошла визуальная деградация: список обращений и сообщения отображались как базовая разметка без ожидаемой карточной сетки и рабочих отступов.

Пользовательский симптом: в админском экране поддержки обращения выглядели как обычный маркированный список, а не как список карточек с выделением активного диалога.

## Что именно считалось поломкой

1. Блок обращений не имел визуальной структуры (`admin-support-list*` классы не применялись).
2. Правая панель диалога не имела ожидаемого контейнера (`admin-support-thread*` стиль отсутствовал визуально).
3. Общие блоки поддержки (`support-*`) рендерились без фоновых контейнеров, выравнивания и состояния элементов.

## Root Cause Analysis

1. Функциональные React-страницы и backend API поддержки присутствовали и работали корректно:
- `frontend/src/pages/SupportPage.tsx`
- `frontend/src/pages/AdminSupportPage.tsx`
- backend маршруты `/api/v1/support/*` и `/api/v1/admin/support/*`
2. В production-версии `frontend/src/styles/global.css` отсутствовал блок стилей для `support-*` и `admin-support-*`.
3. Из-за отсутствия CSS классов браузер показывал нативное поведение HTML-элементов (`ul/li`), что выглядело как «даунгрейд» UI.

## Техническое исправление (пошагово)

1. Сверена разница между рабочей версией стилей и текущим production-состоянием.
2. Восстановлен полный блок стилей поддержки в:
- `frontend/src/styles/global.css`
3. Восстановленные селекторы включают:
- `support-page`, `support-empty`, `support-error`, `support-messages`, `support-message-*`, `support-composer-*`
- `admin-support-page`, `admin-support-list*`, `admin-support-thread*`
- `support-attachment-link` и состояния hover/focus
4. Локально выполнена сборка фронтенда для валидации отсутствия синтаксических/сборочных ошибок.
5. Файл стилей синхронизирован на production.
6. Выполнен production deploy:
- `SKIP_DB_BACKUP=true bash deploy/server/deploy.sh`
7. После deploy проверено, что в актуальном бандле CSS присутствуют селекторы `admin-support-page` и `support-*`.

## Почему сделано именно так

1. Проблема была не в API и не в данных, а в слое презентации, поэтому корректное решение — восстановление и поставка missing CSS, а не переделка логики страниц.
2. Восстановлен именно полный блок стилей поддержки, чтобы убрать частичные визуальные регрессии в разных состояниях экрана (список, тред, вложения, composer).
3. Fix внесён в основной источник стилей (`global.css`) и затем прогнан через стандартный production pipeline, чтобы исключить расхождение между локальной и production сборкой.

## Проверка результата

1. Deploy завершён успешно, health checks пройдены.
2. Production HTML ссылается на новый CSS-бандл.
3. В отданном production CSS-бандле найдены селекторы `admin-support-page` и связанный блок `support-*`, что подтверждает доставку фикса на боевой контур.

## Риск и профилактика регрессий

1. Риск повторения связан с неполной синхронизацией крупных CSS-блоков между ветками.
2. Для снижения риска необходимо при релизе изменений поддержки добавлять проверку присутствия `support-*`/`admin-support-*` селекторов в итоговом `dist/assets/index-*.css`.
3. Для ревью рекомендуется считать изменение UI поддержки неполным, если есть React-страницы и API, но отсутствует зафиксированная проверка наличия соответствующих production-стилей.
