# Dashboard: кликабельные строки задач в "Последние отправки" (2026-05-08)

## Контекст и исходная проблема

1. На странице Dashboard блок `Последние отправки` показывал список последних задач пользователя.
2. Визуально строки выглядели как интерактивные элементы, но технически рендерились как `div`, а не как ссылка.
3. Из-за этого пользователь не мог кликнуть по задаче и сразу перейти к исправлению решения.
4. Практический эффект: лишние шаги в учебном потоке (`Dashboard -> Задачи/Проверки -> поиск нужной задачи вручную`), что создавало ощущение "не кликается".

## Что изменено в коде

Файл: `frontend/src/pages/DashboardPage.tsx`

1. Расширен тип `SubmissionItem`:
- добавлено поле `taskId?: string`, чтобы использовать id задачи из ответа `submissionHistory()`.

2. Переведён рендер строк в блоке `Последние отправки`:
- было: `<div className="clean-list-row">...</div>`;
- стало: `<Link className="clean-list-row clean-list-link" ...>...</Link>`.

3. Добавлена навигация с привязкой к задаче и отправке:
- при наличии `taskId`: переход в `/tasks/:taskId?submissionId=:id`;
- при отсутствии `taskId`: fallback в `/tasks` (без битых ссылок для legacy-строк).

4. Добавлена доступность:
- `aria-label="Открыть задачу: <название задачи>"` на ссылке строки.

## Как работает после фикса

1. Каждая строка в `Dashboard -> Последние отправки` стала кликабельной.
2. Переход открывает нужную задачу сразу в контексте конкретной отправки (`submissionId`), если backend вернул `taskId`.
3. Даже если `taskId` отсутствует в записи истории, пользователь попадает в каталог задач и не сталкивается с "мертвой" строкой.

## Почему реализовано именно так

1. Изменение точечное и минимально рискованное: бизнес-логика проверок не меняется, меняется только интерактивный контейнер строки.
2. Паттерн маршрута повторяет уже существующий поток из страницы `Проверки`, поэтому поведение консистентно для пользователя.
3. Fallback на `/tasks` выбран, чтобы сохранить работоспособность с историческими/неполными данными и исключить пустые переходы.
