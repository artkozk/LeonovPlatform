# Disk Retention Autocleanup (Production)

Дата внедрения: 2026-05-05 (UTC+3)
Сервер: `root@85.198.82.221`

## 1. Почему была нужна автоматизация

На сервере регулярно накапливался технический мусор (диагностические дампы, временные артефакты, исторические backup-папки релизов и крупные логи), из-за чего диск доходил до опасных значений заполнения.

Цель: удерживать заполнение диска в безопасном диапазоне без удаления актуальных рабочих данных.

## 2. Что было настроено

Создан ежедневный `systemd timer`, который запускает `oneshot`-сервис очистки.

- Скрипт очистки: `/usr/local/sbin/lcp-disk-retention.sh`
- Unit сервиса: `/etc/systemd/system/lcp-disk-retention.service`
- Unit таймера: `/etc/systemd/system/lcp-disk-retention.timer`

Расписание:

- `OnCalendar=*-*-* 03:40:00`
- `RandomizedDelaySec=12m`
- `Persistent=true` (если сервер был выключен в момент запуска, задача будет выполнена после старта)

## 3. Политика retention (текущая рабочая версия)

### 3.1 LeonovCare deploy backups

Путь: `/opt/leonovcare-platform`

- Папки вида `current_backup_*`, `current_new_*`, `current_prelink_*`:
  - сохраняем **6** самых новых
  - старые удаляем
- Архивы `*.tgz`:
  - сохраняем **10** самых новых
  - старые удаляем

Почему так:

- 6 каталогов достаточно для быстрого отката по ближайшим деплоям.
- 10 архивов достаточно для короткой ретроспективы релизов и не раздувает диск.

### 3.2 Mentor bot parser runs

Путь: `/opt/mentor-bot/data/owner_tools/parser_runs`

- Удаляются только **файлы старше 7 дней**.
- Пустые директории удаляются.

Почему так:

- Последняя неделя сохраняется для диагностики и сверок.
- Старые выгрузки (`hh_resumes_*.json`) являются основным источником роста, но не нужны для постоянного хранения на проде.

### 3.3 HH autoresponder dumps

Путь: `/opt/hh-autoresponder/pw-dumps`

- Удаляются записи старше **2 дней**.

Почему так:

- Эти дампы нужны для оперативной отладки в ближайшие сутки.
- Более старые диагностические снимки редко полезны, но занимают значительный объём.

### 3.4 /tmp

Путь: `/tmp`

- Удаляются объекты старше **2 дней** (в пределах `xdev`).

Почему так:

- Эфемерные временные файлы не должны жить долго.
- Ограничение по возрасту снижает риск удалить то, что может понадобиться активному процессу в краткосрочном окне.

### 3.5 Логи

- `/root/.pm2/logs`: truncate только логов > **200 MB**.
- `/opt/hh-autoresponder/logs/service.out`: truncate только если файл > **200 MB**.

Почему так:

- Не удаляем все логи подряд, а режем только аномально разросшиеся файлы.
- Сохраняем рабочую отладочную полезность логов.

### 3.6 System journal

- `journalctl --vacuum-size=500M`

Почему так:

- Сохраняется достаточно системного журнала для расследований.
- Предотвращается неконтролируемый рост `/var/log/journal`.

## 4. Безопасность удаления

В скрипте удаление ограничено шаблонами путей:

- Для backup-директорий удаляются только пути с префиксами `current_backup_*`, `current_new_*`, `current_prelink_*` внутри `/opt/leonovcare-platform`.
- Для архивов удаляются только `*.tgz` внутри `/opt/leonovcare-platform`.
- Остальные очистки выполняются на конкретно заданных каталогах.

Это сделано, чтобы исключить случайное удаление данных за пределами ожидаемой зоны.

## 5. Проверка после внедрения

Команды верификации:

```bash
systemctl list-timers --all | grep lcp-disk-retention
systemctl status lcp-disk-retention.service --no-pager
journalctl -u lcp-disk-retention.service -n 100 --no-pager
df -h /
```

Ожидаемое состояние:

- таймер `lcp-disk-retention.timer` присутствует и имеет `NEXT` запуск;
- сервис завершается со статусом `0/SUCCESS`;
- в логах есть этапы `cleanup_*` без аварий;
- заполнение `/` стабилизировано.

## 6. Что делать, если нужно изменить retention

1. Отредактировать переменные в `/usr/local/sbin/lcp-disk-retention.sh`.
2. Запустить вручную:

```bash
systemctl start lcp-disk-retention.service
journalctl -u lcp-disk-retention.service -n 100 --no-pager
```

3. Убедиться, что очистка работает корректно и не удаляет лишнее.

## 7. Как временно отключить автоочистку

```bash
systemctl disable --now lcp-disk-retention.timer
```

Включить обратно:

```bash
systemctl enable --now lcp-disk-retention.timer
```

## 8. Почему решение считается необходимым

- До внедрения фиксировались периодические скачки использования диска за счёт технических артефактов.
- После ручной очистки и запуска автоматизации остаётся большой запас свободного места.
- Политика retention выбрана консервативно: сохраняются недавние rollback-артефакты и оперативные логи, удаляются только устаревшие технические накопления.
