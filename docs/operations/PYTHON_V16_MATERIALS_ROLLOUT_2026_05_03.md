# Python v16 Materials Rollout — 2026-05-03

## 1. Контекст

Нужно заменить текущий учебный контент курса `python-zero` на новую поставку из папки `материалы`, сохранив рабочие сценарии:

1. Практика с выполнением кода (`run` + `submit`).
2. Тестовые шаги уроков (quiz-check через backend).
3. Шаблоны кода в редакторе.
4. AI-подсказки по задаче.
5. Совместимость с IDEA-плагином (типы задач, файлы, project-check шаги).

Почему rollout выполняется миграцией, а не ручной правкой:

1. Миграция воспроизводима и прозрачна в ревью.
2. Полный reseed не оставляет “полуобновлённого” состояния между уроками/шагами/тасками.
3. Можно проверять согласованность контента автоматически перед деплоем.

## 2. Источник данных

Единый источник импорта:

1. `материалы/course_import.json`

Структура источника:

1. `modules=5`

4. step types: `theory/practice/test/project/summary`
5. checker types: `python_stdout`, `python_pytest`, `sql_query`, `http_api`, `ide_plugin`, `quiz_single`

Назначение:

2. Преобразовывать шаги урока в `lessons`, `lesson_blocks`, `tasks`, `task_test_cases`.
3. Выпускать полную миграцию reseed для `python-zero`.

### 3.2 Сгенерированная миграция

Добавлена миграция:

1. `backend/migrations/025_reseed_python_zero_v16_materials.sql`

Назначение миграции:

1. Переопубликовать `python-zero` с контентом из `материалы`.
2. Деактивировать (`is_published=false`) старые шаги/задачи этого курса.
3. Сохранить новый набор шагов и задач в publish-состоянии.

### 3.3 Почему нужна нормализация checker-форматов

Исходные `checker` в `материалы` частично не совпадают с runtime-структурами backend, поэтому генератор делает адаптацию.

Ключевые адаптации:

1. `python_pytest`: `test_code -> pytest_code`.
2. `http_api`: `public_tests + hidden_tests -> tests[]` c `expected_json`.
3. `sql_query`: собирается `init_sql` из `schema_sql + seed_sql`, checks нормализуются для текущего SQL judge.
4. `test` шаги курса переводятся в `lesson_blocks.block_type='quiz'` и `quiz_payload.questions[]`.

Почему так сделано:

1. Без этого `run/submit` и часть project/API шагов будут падать при исполнении checker runtime.
2. Адаптация выполнена в генераторе, чтобы runtime оставался стабильным и обратносуместимым.

## 6. Операционная инструкция деплоя этого контента

1. Обновить код на сервере.
2. Выполнить стандартный deployment script (`deploy/server/deploy.sh`), где `AUTO_MIGRATE=true`.
3. Проверить, что версия миграции `025_reseed_python_zero_v16_materials` появилась в `schema_migrations`.
4. Проверить агрегаты курса SQL-запросами из runbook.
5. Пройти smoke:
   - открыть урок с практикой;
   - выполнить `Запустить код`;
   - сделать `Отправить на проверку`;
   - получить `AI-подсказку`;
   - проверить quiz step через `Проверить ответ`.

Почему именно такой порядок:

1. Сначала подтверждается схема/данные.
2. Затем подтверждается учебный UX.
3. Финально проверяется AI и quiz-security слой.
