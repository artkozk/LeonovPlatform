# LESSON_CONTENT_AND_CHECKER_FEEDBACK_HARDENING_2026_05_22

Дата: 2026-05-22  
Контур: frontend + генератор учебного контента Java (metanit)

## Цель изменений

Исправить набор UX-дефектов в уроках и практике:

1. Убрать ссылки на источник из теории в пользовательском интерфейсе.
2. Убрать формулировки, которые намекают пользователю на возможный баг платформы.
3. Сделать теоретический текст более читаемым за счет абзацев, не меняя сам текст.
4. Убрать наложение пунктов в выпадающем списке квиза.
5. Зафиксировать эти правила также в генераторе контента, чтобы новые импорты сразу были в корректном формате.

## Что изменено

### 1) Санитация markdown-контента урока на фронтенде

Файл: `frontend/src/pages/LessonPage.tsx`

Добавлены функции:

- `stripSourceMentions(markdown)`
- `insertTheoryParagraphs(markdown)`
- `normalizeLessonContentMarkdown(raw)`

Что делает каждая функция:

- `stripSourceMentions`:
  - удаляет строки вида `Источник: <url>` в markdown;
  - заменяет заголовок `### Код из источника` на `### Пример кода`;
  - нормализует избыточные пустые строки.
- `insertTheoryParagraphs`:
  - обрабатывает только секцию `### Подробная теория`;
  - если теория идет «монолитом», вставляет разрывы абзацев каждые 3 предложения;
  - не меняет лексический состав текста (добавляет только переносы строк).
- `normalizeLessonContentMarkdown`:
  - объединяет оба шага перед рендером.

Подключение:

- в нормализации блоков урока поле `contentMd` теперь заполняется через `normalizeLessonContentMarkdown(block.contentMd)`.

Почему так:

- исправление начинает работать сразу для уже загруженных в БД уроков;
- не нужен ручной реимпорт курса для каждого окружения;
- соблюдается требование «текст не менять», так как меняется только разметка/переносы.

### 2) Обновление пользовательских сообщений по результатам проверки

Файлы:

- `frontend/src/pages/LessonPage.tsx`
- `frontend/src/pages/TaskPage.tsx`

Изменения:

- для статуса `failed` убрана формулировка про сбой сервера;
- текст заменен на нейтральный: `Проверка не завершилась. Проверьте решение по логу и отправьте снова.`
- в `ruError()` добавлены явные маппинги `internal server error`, `service unavailable`, `bad gateway`, `timeout` на нейтральные пользовательские сообщения;
- убран возврат «сырых» backend-строк в дефолтном кейсе (`return raw`), чтобы технические тексты не попадали напрямую в UI.

Почему так:

- интерфейс больше не транслирует пользователю внутренние технические причины;
- исключен намек на возможный баг платформы в пользовательском тексте;
- сообщение остается actionable: пользователь понимает, что делать дальше.

### 3) Фикс визуального конфликта выпадающего списка в квизе

Файл: `frontend/src/styles/global.css`

Изменения в `.custom-select-menu`:

- `position: absolute` -> `position: relative`
- сброшены `top/left/right`
- добавлен `margin-top: 6px`
- снижен `z-index` до локального уровня контейнера

Результат:

- список больше не «наезжает» поверх соседних вопросов;
- контент ниже сдвигается корректно, без визуального конфликта строк.

Почему так:

- в учебном сценарии важнее стабильная читаемость вопросов, чем overlay-поведение селекта.

### 4) Улучшение читаемости markdown в целом

Файл: `frontend/src/styles/global.css`

Добавлено:

- `margin` для абзацев и элементов списков в `.markdown-content`;
- выравнивание отступов первого/последнего элемента через:
  - `.markdown-content > :first-child { margin-top: 0; }`
  - `.markdown-content > :last-child { margin-bottom: 0; }`

Почему так:

- даже при корректной разбивке на параграфы без CSS-отступов текст продолжает выглядеть «слитно»;
- эти правила обеспечивают видимую абзацность без ручной доразметки каждого урока.

### 5) Правка генератора курса для новых импортов

Файл: `материалы/java_metanit_v1/build_course.py`

Изменения:

- удалено добавление строки `**Источник:** <url>` в `build_theory_markdown`;
- заголовок `### Код из источника` заменен на `### Пример кода`;
- добавлена функция `format_theory_paragraphs(text_lines)`:
  - собирает теорию;
  - разбивает ее на абзацы по 3 предложения;
  - возвращает markdown с пустой строкой между абзацами.

Почему так:

- новые версии импортируемого контента сразу соответствуют UI-стандарту;
- устраняется повторное появление ссылок на источник после следующих генераций.

## Дополнение 2026-05-22 (уточнение по квизу dropdown)

После первичной правки был уточнен UX-требование по квизу:

1. Варианты ответов должны отображаться поверх следующих вопросов (overlay-режим), как и раньше.
2. Основной дефект заключался не в положении меню, а в том, что список мог оставаться открытым дольше ожидаемого.

Что дополнительно изменено:

1. Для `.custom-select-menu` возвращен overlay-режим (`position: absolute` с прежними координатами).
2. Для открытого селекта добавлен явный класс `.lesson-quiz-select-wrap.is-open`, который поднимает `z-index` и удерживает меню поверх соседних вопросов, даже если `focus-within` уже потерян.
3. Закрытие списка усилено:
- закрытие на `pointerdown` вне селекта (вместо только `mousedown`), чтобы корректно работать и мышью, и тач-вводом;
- закрытие при прокрутке окна/контейнера;
- при выборе варианта используется `onMouseDown` с `preventDefault` + централизованное закрытие, чтобы исключить повторное открытие из-за последовательности событий клика.

Почему сделано именно так:

1. Сохраняется привычное визуальное поведение (overlay поверх вопросов).
2. Устраняется причина «список не скрывался назад» без изменения контентной логики квиза.
3. Решение покрывает десктоп и мобильный сценарий ввода через pointer events.

### Дополнение 2026-05-22 (AI-подсказка после завершенной проверки)

Контекст проблемы:

1. Пользователь нажимал кнопку `AI-подсказка` после завершенной автопроверки (в том числе при `compile_error`).
2. В ряде случаев backend для подсказки возвращал `502` с `internal server error`.
3. На фронтенде это маппилось в сообщение про незавершенную проверку, хотя речь была не о проверке, а о генерации подсказки.

Что изменено в backend:

Файл: `backend/internal/app/handlers_ai.go`

1. В `TaskHint` изменена ветка обработки ошибки `requestAIHint`:
- раньше локальный fallback применялся только для region-restriction ошибок;
- теперь локальный fallback применяется для любой ошибки провайдера AI.
2. Добавлен отдельный лог-статус `fallback_openai_error` (для нерегиональных ошибок) и сохранен `fallback_region_restricted` (для региональных).
3. Ответ API в обоих fallback-сценариях возвращается как успешный (`status: ok`, `model: local-fallback`) с готовым текстом подсказки, чтобы UI не показывал техническую ошибку вместо учебного шага.
4. В `loadLatestSuccessfulHint` расширен список статусов успешной истории подсказок: добавлен `fallback_openai_error`.

Почему сделано именно так:

1. Для учебного сценария приоритет — всегда дать пользователю следующий рабочий шаг, даже если внешний AI-провайдер временно недоступен.
2. Пользовательская сессия не должна обрываться техническим `502`, когда можно выдать локальную учебную подсказку.
3. Сохранение fallback-ответов в успешной истории нужно, чтобы следующая подсказка учитывала уже выданный контекст, а не начинала с нуля.

Что изменено в тексте локальной fallback-подсказки:

Файл: `backend/internal/app/handlers_ai.go`, функция `buildLocalHintFallback`

1. Убран заголовок с техническим пояснением про fallback-режим и недоступность провайдера.
2. Подсказка приведена к учебному формату:
- `Следующий шаг`
- `Зачем этот шаг`
- `Проверь себя`
- `Как получить следующий шаг`
3. Добавлен `Короткий чек-лист` для закрепления шага без публикации технических деталей инфраструктуры.

Почему сделано именно так:

1. Пользователь не должен видеть оправдательные или инфраструктурные формулировки на продовой платформе.
2. Формат остается педагогическим и совместимым с текущим UX-потоком кнопки `AI-подсказка`.

Что изменено во frontend для ошибок AI-подсказки:

Файлы:
- `frontend/src/pages/TaskPage.tsx`
- `frontend/src/pages/LessonPage.tsx`

1. Добавлена отдельная функция маппинга `ruHintError(...)` для ошибок запроса `AI-подсказка`.
2. В `onHint()` заменен вызов общего `ruError(...)` на `ruHintError(...)`.
3. В fallback-сообщении для AI-подсказки используется нейтральный текст: `Не удалось получить AI-подсказку. Повторите действие.`
4. Сохранены отдельные пользовательские ответы для `upgrade_required`, `unauthorized`, `forbidden`.

Почему сделано именно так:

1. Ошибки подсказки и ошибки автопроверки — разные пользовательские сценарии и должны иметь разные тексты.
2. Убирается ложная привязка к состоянию проверки (`Проверка не завершилась`) в кейсе, когда проблема была именно в генерации AI-подсказки.
