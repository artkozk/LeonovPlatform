# Серверный маршрут Gemini через прокси

Дата: 15 августа 2026 года.

## Зачем изменён маршрут

Предыдущая production-конфигурация использовала Vertex AI Express Mode. Google распознавал ключ и проект, но блокировал генерацию ошибкой `BILLING_DISABLED`. Сам пользователь не должен настраивать Google Cloud billing, service account или OAuth, поэтому этот путь заменён на уже проверенный Gemini Developer API.

Прямой вызов Gemini Developer API с российского production-IP ранее возвращал региональный `FAILED_PRECONDITION`. Основатели явно разрешили использовать один внешний прокси только как транспорт исходящих AI-запросов. Предварительная проверка с основного сервера через выбранный прокси вернула HTTP 200 и полноценный ответ Gemini 2.5 Flash.

## Текущий поток данных

```text
браузер основателя
  -> HTTPS control.e-rd.ru
  -> business-control на 159.194.231.150
  -> HTTP CONNECT к серверному прокси
  -> TLS-соединение с generativelanguage.googleapis.com
  -> Gemini 2.5 Flash
```

Приложение, SQLite, вложения, сессии, резервные копии и ключи остаются только на `159.194.231.150`. Прокси используется исключительно как сетевой транспорт к внешнему AI-провайдеру. В браузер proxy URL и Gemini API key не передаются.

## Реализация

- `AI_PROXY_URL` загружается только из server env.
- `GEMINI_BASE_URL` по умолчанию равен `https://generativelanguage.googleapis.com/v1beta`.
- Для AI создаётся отдельный `http.Client` с клонированным стандартным transport и ограниченными timeout.
- Этот клиент используется всеми вызовами Gemini и Groq; глобальный `http.DefaultClient` не изменяется.
- Допустимы схемы `http`, `https` и `socks5`.
- Некорректный proxy URL не приводит к прямому запросу. Внешний AI считается недоступным, а продукт продолжает работу на локальной эвристике.
- `/api/ai/health` возвращает только безопасный признак `route=proxy` или `route=direct`.
- Ответ модели декодируется как JSON и проходит серверную проверку типов, диапазонов, допустимых статусов и существования связанных карточек.
- Для структурированного JSON задан `thinkingBudget=0`: скрытое рассуждение не должно расходовать лимит ответа и оставлять пустую content-part.
- AI создаёт только предложение. Изменения карточек без подтверждения основателя запрещены.

## Конфиденциальность и остаточный риск

При стандартном HTTP CONNECT содержимое запроса и ответа защищено сквозным TLS между приложением и Google. Прокси видит факт обращения к Google, время, длительность и объём трафика. Если прокси попытается подменить TLS-сертификат, стандартная проверка сертификата в Go отклонит соединение.

Доступность и политика хранения метаданных внешнего прокси не контролируются платформой. Поэтому через AI нельзя отправлять пароли, API keys, банковские реквизиты или иные секреты. Карточки могут содержать деловой контекст, и отправка их текста в Gemini остаётся осознанным внешним процессингом. При недоступности прокси система не блокирует основную работу.

## Секреты

`AI_PROXY_URL` может содержать логин и пароль, поэтому применяется тот же режим, что и для `GEMINI_API_KEY`:

- файл `/etc/business-control.env` принадлежит `root:root` и имеет mode `0600`;
- значение не помещается в Git, SQLite, JSON-экспорт, activity, логи или зашифрованную резервную копию данных приложения;
- health и UI не показывают host, port, username или password;
- ошибки конфигурации нормализуются и не включают исходное значение;
- после смены прокси требуется `systemctl restart business-control` и повторный реальный smoke.

## Проверяемые инварианты

1. При заданном валидном `AI_PROXY_URL` тестовый proxy получает запрос Gemini.
2. При повреждённом URL клиент не создаётся и direct fallback отсутствует.
3. Health считается успешным только при `providerAvailable=true`, `source=gemini`, `route=proxy`.
4. Production smoke дополнительно вызывает пользовательский `/api/ai/suggest-record` и требует `source=gemini`.
5. При любой ошибке AI CRUD карточек, поиск, задачи, вопросы, сравнения и история продолжают работать.
