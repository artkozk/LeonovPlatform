# Leonov Care Design System v3 (2026-04-23)

## 1. Цель

Документ фиксирует текущую реализацию визуальной системы после полного редизайна и объясняет, почему именно такие решения приняты для продукта уровня premium edtech/tech-platform.

Ключевая цель: обеспечить единый, расширяемый и предсказуемый visual language для всех ключевых экранов:

1. dashboard
2. courses (карта обучения)
3. tasks catalog
4. task workspace (редактор + проверка)
5. leaderboard
6. billing
7. settings
8. auth

## 2. Токены и базовые принципы

Источник: `frontend/src/styles/global.css`.

### 2.1. Layout tokens

1. `--container-max: 1320px`
2. Основной шаг отступов: 8px-система (используется через фиксированные значения 8/10/12/14/16/24/28/40 и т.д.).
3. Радиусы:
- `--radius-sm: 12px`
- `--radius-md: 16px`
- `--radius-lg: 20px`

### 2.2. Цветовые токены (light)

1. Фон: `--bg: #f5f7fb`
2. Основная поверхность: `--surface: #ffffff`
3. Вторичная поверхность: `--surface-soft: #f8fafd`
4. Текст: `--text: #111827`
5. Вторичный текст: `--text-soft: #667085`
6. Акцент: `--accent: #315efb`
7. Служебные:
- success: `--success: #15803d`
- warning: `--warning: #b45309`
- error: `--error: #b42318`

### 2.3. Цветовые токены (dark)

1. Фон: `--bg: #0b1220`
2. Поверхности: `--surface: #111b2f`, `--surface-soft: #15223a`
3. Текст: `--text: #e7edf7`, вторичный `--text-soft: #a6b4c9`
4. Акцент: `--accent: #5f85ff`
5. Служебные цвета адаптированы по контрасту и читаемости.

### 2.4. Тени и depth

1. `--shadow-sm` — микро-глубина для обычных карточек.
2. `--shadow-md` — усиленная depth для hero и ключевых поверхностей.
3. Принцип: без агрессивных теней, depth только для иерархии.

## 3. Компонентные правила

### 3.1. Surface

1. Класс `surface` — базовая карточка/контейнер.
2. `hero-surface` — выделенная композиционная поверхность для первого экрана.
3. Правило: сначала иерархия через размер/контент, потом через цвет/тень.

### 3.2. Buttons

1. База: `.btn`.
2. Варианты:
- `.btn-primary` — главный CTA;
- `.btn-secondary` — нейтральное действие;
- `.btn-ghost` — минимальный служебный action.
3. Размеры:
- default 44px;
- small (`.btn-sm`) 38px;
- large (`.btn-lg`) 50px.

### 3.3. Fields

1. Поля и селекты: высота 48px.
2. Единый `focus` с accent ring.
3. Placeholder не конкурирует с основным текстом.

### 3.4. Status / Badge

1. Бейджи: `.badge` + модификаторы `neutral/accent/success/warning/error`.
2. Сообщения: `status-box`, `status-box-error`.
3. Пустые состояния: `empty-state`.

### 3.5. Loading states

1. `skeleton-list`
2. `skeleton-line`
3. Shimmer-анимация как индикатор загрузки без визуального шума.

## 4. Навигационная архитектура

## 4.1. App shell

1. Sticky top-header (`app-header`) вместо тяжелого постоянного sidebar.
2. Структура:
- слева бренд;
- центр — глобальная навигация;
- справа — профиль/тариф/выход.
3. Добавлен раздел `Задачи` как обязательный вход в практику.

### 4.2. Почему так

1. Снижается “админ-ощущение”.
2. Сохраняется масштабируемость (добавление новых product-направлений через nav).
3. Улучшается мобильная адаптация: горизонтальный scroll nav вместо перегруженного бокового меню.

## 5. Экранные композиции (актуальная реализация)

### 5.1. Dashboard

1. Hero: статус + прогресс + next action.
2. KPI-линия: уровень/xp/серия/принятые.
3. Основная сетка: activity feed + achievements.

### 5.2. Courses

1. Hero overview.
2. Sidebar треков.
3. Learning path с состояниями `completed/in_progress/available/locked`.

### 5.3. Tasks catalog

1. Фильтры (курс/сложность/поиск).
2. Продуктовый список задач.
3. Быстрый переход в `TaskPage`.

### 5.4. Task workspace

1. Split-view: statement + editor.
2. Единый action-bar.
3. Структурные блоки результата проверки и логов.

### 5.5. Billing

1. Hero со статусом текущей подписки.
2. Pricing-grid с featured plan.
3. Отдельный блок прозрачности платежного сценария.

### 5.6. Leaderboard

1. Hero + позиция пользователя.
2. Podium top-3.
3. Полная таблица с выделением текущего пользователя.

### 5.7. Settings

1. Разделение по смысловым секциям:
- интерфейс;
- редактор;
- уведомления.
2. Единый визуальный ритм полей и toggle-блоков.

### 5.8. Auth

1. Desktop: бренд-панель + форма.
2. Mobile/tablet: одно-колоночная адаптация.
3. OAuth и email-flow работают в единой компонентной системе.

## 6. Responsive-правила

1. `@media (max-width: 1220px)`:
- hero и двухколоночные рабочие зоны переходят в 1 колонку;
- nav становится скроллируемой по X.
2. `@media (max-width: 780px)`:
- компактные padding на всех surface;
- KPI и pricing в 1 колонку;
- activity/path/achievement карточки переходят в вертикальный формат.

## 7. Состояния интерактивности

Все интерактивные элементы имеют:

1. default
2. hover
3. focus-visible
4. disabled
5. loading (через текст+disable/skeleton)
6. empty
7. success/error message states

## 8. Почему эта версия считается системной, а не косметической

1. Вынесены и нормализованы токены.
2. Заменен корневой layout-pattern.
3. Пересобраны все ключевые продуктовые экраны.
4. Введены единые компоненты состояний и компонентные контракты.
5. Обеспечена база для дальнейшего масштабирования без визуальной деградации.

## 9. Дополнение от 2026-04-29 (lesson/practice premium refresh)

Ниже фиксируется расширение текущей дизайн-системы без удаления предыдущих принципов.

### 9.1. App header (workspace shell)

1. Брендинг в шапке упрощён до одного текстового маркера `Leonov Care` (без квадратной иконки и без подписи).
2. Навигация переведена в чистый горизонтальный ритм:
- белый фон;
- тонкая нижняя граница `1px`;
- активный пункт через синий текст + тонкий нижний индикатор.
3. Блок пользователя (`имя`, `FREE • L1`, `Выйти`) оставлен справа для сохранения знакомого сценария управления сессией.

### 9.2. Lesson composition

1. Урок теперь начинается с отдельной overview-карточки:
- иконка академического контекста;
- title/subtitle;
- progress pill `Шаг N из M`.
2. Рабочая зона урока зафиксирована как desktop-first `sidebar + main`:
- sidebar 300-340px;
- контентная карточка справа с увеличенным whitespace.
3. Step list получила state-language:
- `current`;
- `completed`;
- `default`.
4. Стили stepper ориентированы на мягкие бордеры/тени и тонкий скроллбар без визуального шума.

### 9.3. Practice card + editor surface

1. Практика оформлена отдельной карточкой с явной иерархией:
- заголовок задания;
- описание;
- формула;
- badges (`LANGUAGE`, `Difficulty`, `XP`).
2. Monaco editor не заменялся и не упрощался до статичного блока; обновлена только оболочка:
- toolbar;
- премиальные радиусы/границы;
- аккуратный фон canvas.
3. Кнопка `Отправить на проверку` закреплена как главный CTA; остальные действия приведены к secondary-outline роли.

### 9.4. Причина изменений

1. Требование пользователя было про повышение визуального уровня при неизменной бизнес-логике.
2. Поэтому дизайн-слой изменён в существующих компонентах, а не в отдельной дублирующей странице.
3. Такой подход снижает риск регрессий и позволяет ревьюеру отследить причинно-следственную связь между UX-целью и конкретными UI-правками.

### 9.5. Уточнение от 2026-04-29 (content integrity и control semantics)

1. В practice-card запрещено эвристически «вытаскивать формулы/строки» из Markdown-условия задачи.
2. Отображение задания должно идти из исходного `statement_md` целиком, иначе возможно искажение смысла (пример: строка `name = "Анна"` может ошибочно восприниматься как отдельный UI-токен-подсказка).
3. Toolbar-контролы редактора должны нести фактическую нагрузку:
- control справа от language-pill отвечает за expand/collapse рабочей области редактора;
- декоративные нерабочие controls в учебном потоке не допускаются.

## 10. Дополнение от 2026-04-29 (единый минималистичный SaaS-редизайн без изменения бизнес-логики)

Ниже фиксируется новая актуальная версия UI. Предыдущие разделы сохранены как исторический контекст, удалений не выполнялось.

### 10.1. Глобальные токены и визуальная база

1. Принят светлый рабочий фон `#F6F8FC` как основной слой всех продуктовых страниц.
2. Базовая карточка приведена к единому стандарту:
- `background: #FFFFFF`;
- `border: 1px solid #E2E8F0`;
- `border-radius: 20px`;
- мягкая тень low-contrast уровня.
3. Базовая типографика и контраст приведены к спокойной иерархии:
- основной текст `#0F172A`;
- вторичный текст `#64748B`;
- muted текст `#94A3B8`.
4. Кнопки, бейджи, поля и таблицы переведены в единую систему радиусов и состояний hover/focus/disabled.

Почему так:

1. Требовался цельный product-style интерфейс, а не набор локальных правок по страницам.
2. Единые токены позволяют масштабировать UI без визуальной фрагментации.

### 10.2. Header и навигация

1. В левом блоке шапки оставлен только текстовый бренд `Leonov Care`.
2. Основная навигация приведена к целевому составу:
- `Главная`;
- `Обучение`;
- `Задачи`;
- `Проверки`;
- `Рейтинг`.
3. `Подписка` и `Настройки` убраны из main-nav и перенесены в профильное меню пользователя.
4. Активный пункт main-nav переведен в мягкий синий pill-state (без underline).

Почему так:

1. Навигация стала короче и практичнее для ежедневного учебного сценария.
2. Вторичные разделы не конкурируют с ключевым учебным потоком.

### 10.3. Dashboard как операционный центр

1. Удалены декоративный welcome-hero и дублирующие CTA-кнопки.
2. Добавлена ключевая карточка `Текущий курс` с блоком `Следующий шаг` и прогрессом урока.
3. Метрики переведены в компактный практический формат:
- `Уровень`;
- `XP`;
- `Серия`;
- `До L+1`.
4. Правая нижняя карточка переведена из общего achievements-формата в блок `Что разобрать`.

Почему так:

1. Экран теперь помогает действовать (следующий шаг, прогресс, проверка), а не только отображает статус.
2. Снижена визуальная и текстовая нагрузка на первом экране.

### 10.4. Курсы/уроки/практика

1. Раздел `Курсы` в интерфейсе переименован в `Обучение` (route и API не менялись).
2. Страница обучения показывает:
- текущий курс;
- модули;
- уроки со статусами;
- прогресс по шагам.
3. Страница урока сохранена в рабочем step-flow, но визуально пересобрана:
- чистая верхняя карточка урока;
- аккуратный sidebar шагов;
- мягкое выделение текущего шага;
- единые статус-индикаторы completed/current/default.
4. Monaco-редактор сохранен рабочим; обновлена только оболочка (toolbar, border, радиусы, состояние expand, статусная точка).

Почему так:

1. Требование пользователя: редизайн без замены рабочего редактора и без ломки учебной логики.
2. Изменения выполнены только на presentation-layer, без изменения API-контрактов.

### 10.5. Задачи, проверки, рейтинг

1. Страница `Задачи` переведена в карточный минималистичный каталог с фильтрами и статус-плашками.
2. Добавлена отдельная страница `Проверки` (`/checks`) на реальных данных `submissionHistory`.
3. Страница `Рейтинг` переведена в clean-table с мягким выделением top-3 и текущего пользователя.

Почему так:

1. Сценарии `решить -> отправить -> посмотреть статус -> сравнить результат` теперь визуально связаны и последовательны.
2. Новая страница проверок закрывает отдельный пользовательский запрос на явную историю отправок.

### 10.6. Политика по эмодзи в UI

1. Из интерфейсных компонентов удалены emoji-элементы.
2. В частности, маркер style-hint в Monaco больше не использует emoji-глиф, заменен на нейтральный status-dot.
3. Для статусов и пустых состояний используются SVG/outline-иконки и текстовые плашки.

Почему так:

1. Эмодзи давали визуальную несогласованность с требуемым premium/minimalist стилем.
2. Единый outline-подход улучшает целостность интерфейса.

## 11. Дополнение от 2026-04-29 (v2.43: unified minimal SaaS redesign)

Исторические секции документа сохранены без удаления. Ниже зафиксирована текущая рабочая версия визуальной системы после полного редизайна интерфейса.

### 11.1. Базовые токены (актуальное состояние)

1. `frontend/src/styles/global.css` переведен на токены уровня дизайн-системы:
- `--font-sans`, `--font-mono`;
- `--color-page`, `--color-surface`, `--color-surface-soft`;
- `--color-text`, `--color-text-secondary`, `--color-text-muted`;
- `--color-border`, `--color-border-soft`;
- `--color-primary`, `--color-primary-hover`, `--color-primary-soft`, `--color-primary-border`;
- status-токены (`success/warning/danger`) и radii/shadows.
2. Для совместимости с существующим css-layer сохранены alias-переменные (`--bg-page`, `--surface`, `--primary` и др.), чтобы редизайн не требовал массового risky-рефакторинга всех старых селекторов.

Почему так:

1. Это позволяет быстро привести весь продукт к единому виду и одновременно сохранить стабильность существующего кода.
2. Alias-слой уменьшает риск regressions при больших визуальных релизах.

### 11.2. Типографика

1. Основной UI-stack: `Inter` с fallback на `Manrope` и системные sans.
2. Кодовый stack: `JetBrains Mono` с fallback на `SFMono/Consolas`.
3. Глобальные правила:
- `html` использует anti-aliased rendering;
- `body` использует светлый фон и плотность текста в стиле product UI;
- заголовки получают усиленный weight и более плотный tracking.

Почему так:

1. Главная цель — читаемость и «дорогая» нейтральная подача без визуальной агрессии.
2. Разделение UI-font и code-font критично для учебных экранов с редактором.

### 11.3. Header и навигация

1. Header закреплен как белая полоса с тонкой нижней границей и высотой 72px.
2. Навигация оставлена только по ключевым учебным маршрутам:
- `Главная`;
- `Обучение`;
- `Задачи`;
- `Проверки`;
- `Рейтинг`.
3. Активный пункт nav: soft-blue pill без underline.
4. `Подписка` и `Настройки` вынесены из main-nav в profile-menu.

Почему так:

1. Основной ритм интерфейса не должен конкурировать с вторичными account-разделами.
2. Такой nav-паттерн ускоряет ежедневный учебный сценарий и снижает шум.

### 11.4. Страница обучения и curriculum-подача

1. Добавлен отдельный hero-блок текущего курса:
- иконка курса;
- заголовок/описание;
- прогресс и CTA.
2. Левый блок `Мои курсы` переведен в clean-card список.
3. Правый блок модуля и уроков переведен в curriculum-list:
- divider-строки;
- статус `Текущий урок/Не начат/Завершён`;
- мягкое active-state выделение;
- show-more control для длинных списков.
4. Для Python-курса добавлен встроенный SVG-компонент `PythonCourseIcon`.

Почему так:

1. Пользовательский запрос требовал убрать ощущение «вложенных карточек ради карточек».
2. Curriculum-list быстрее сканируется глазами и лучше подходит для линейного обучения.

### 11.5. Dashboard, Tasks, Checks, Leaderboard, Profile

1. Dashboard переведен в операционный формат:
- текущий курс;
- следующий шаг;
- компактные метрики;
- clean-list последних отправок и тем для разбора.
2. Tasks и Checks переведены в unified list/table ритм:
- меньше декоративных блоков;
- единые статус-pills;
- единый hover/focus-паттерн.
3. Leaderboard очищен до компактной таблицы с soft-highlight текущего пользователя.
4. Добавлена отдельная страница `/profile` с account summary и переходами в billing/settings.

Почему так:

1. Эти экраны формируют ежедневный рабочий путь пользователя, поэтому им нужен единый predictable UX.
2. Отдельная profile-страница разгружает header-меню и делает account-flow прозрачнее.

### 11.6. Принцип «без поломки логики»

1. Редизайн не меняет API контракты и бизнес-потоки:
- auth;
- маршруты учебного пути;
- прогресс/XP/уровни;
- отправки/проверки;
- встроенный редактор и AI-hint flow.
2. Изменения выполнены как presentation-layer реорганизация поверх существующей рабочей логики.

Почему так:

1. Для production-платформы визуальный релиз не должен ломать контентный и учебный runtime.
2. Такой подход уменьшает стоимость регрессионного тестирования и ускоряет безопасный rollout.

4. Type-подача упрощена:
- тип шага оставлен текстом в meta;
- icon-noise в каждой строке убран.
5. Добавлены accessibility и focus-правила:
- активный шаг отмечается `aria-current="step"`;
- сохранены semantic buttons и keyboard focus-visible.

Почему так:

1. Lesson sidebar должен работать как навигационный инструмент, а не как набор конкурирующих визуальных плашек.
2. Timeline-подача делает линейность учебного процесса очевидной и ускоряет сканирование шагов.
3. Этот паттерн масштабируем для длинных модулей и лучше поддерживает premium SaaS визуальную дисциплину.

## 12. Дополнение от 2026-05-02 (light-only UI и удаление Settings)

Исторические разделы выше про `settings` и dark tokens оставлены без удаления, потому что они объясняют прежнюю версию дизайн-системы. Текущее продуктовое правило изменено:

1. Единственная поддерживаемая тема — светлая.
2. Dark tokens больше не активируются в `frontend/src/styles/global.css`.
3. Root shell не выставляет `data-theme`, поэтому внешний вид не зависит от `user.theme`.
4. Monaco editor в `LessonPage` и `TaskPage` всегда использует `light`, чтобы рабочая зона кода визуально совпадала с остальным интерфейсом.
5. Settings screen удалён из пользовательского маршрута:
- `/settings` отсутствует в router;
- пункт `Настройки` отсутствует в profile-menu;
- `/profile` больше не содержит переход к настройкам.

Почему сделано именно так:

1. Settings не был частью частого учебного пути: основные сценарии идут через `Главная`, `Обучение`, `Задачи`, `Проверки`, `Рейтинг`, `Профиль` и `Подписка`.
2. Dark-mode визуально снижал качество продукта и требовал отдельной регрессионной проверки каждого нового UI-блока.
3. Удаление пользовательского входа в настройки упрощает поддержку и делает интерфейс более предсказуемым для первой пользовательской когорты.
4. Backend compatibility сохранён, чтобы старые клиенты и существующая схема БД не ломались из-за UI-упрощения.
